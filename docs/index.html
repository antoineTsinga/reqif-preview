.reqif / .reqifz → HTML

Vos exigences ReqIF, lisibles sans rien d'autre qu'un navigateur.

Une bibliothèque TypeScript universelle (navigateur + Node), sans dépendance à React, Vue ou quoi que ce soit d'autre. Donnez-lui un fichier .reqif ou .reqifz, elle vous rend du HTML — assaini, structuré, personnalisable.

Démarrage

Trois lignes, un fichier, du HTML.

Fonctionne identiquement côté navigateur et côté Node — aucune des deux dépendances (le parseur XML, le dézippage) n'a besoin d'être installée séparément, elles sont incluses dans le paquet.

import { loadReqIfPackage, renderPackageToHtml } from "reqif-preview"; const pkg = await loadReqIfPackage(fileBytes); // .reqif ou .reqifz, peu importe const html = await renderPackageToHtml(pkg); document.querySelector("#preview").innerHTML = html;
Fonctionnalités

Tout ce qui suit est du vrai rendu — pas des maquettes.

Chaque encadré ci-dessous appelle réellement renderPackageToHtml() dans votre navigateur, sur un même exemple de spécification (paiement en ligne). Les interrupteurs EN DIRECT re-rendent l'exemple à chaque clic — et les onglets/panneaux "Détails techniques" sont de vrais composants HTML cliquables, pas des images.

par défaut

Mode simple, détails techniques repliés

Par défaut, chaque exigence n'affiche que son ID, sa date de création/modification et son texte. Tous les autres attributs (chaînes, nombres, énumérations…) vont dans un panneau <details> natif, replié — un clic pour tout voir, zéro JavaScript pour le faire fonctionner.

const html = await renderPackageToHtml(pkg);
ReqIF.Foreign*

ID métier et traçabilité créé/modifié, détectés automatiquement

La convention ReqIF.ForeignID / ReqIF.ForeignCreatedBy/On / ReqIF.ForeignModifiedBy/On (DOORS, ReqEdit, ReqView…) est reconnue d'elle-même, qu'elle soit stockée en chaîne ou en XHTML — vous n'avez rien à configurer.

// rien à faire — déjà actif par défaut const html = await renderPackageToHtml(pkg);

Le panneau technique, lui, reste toujours exhaustif — rien n'y est jamais masqué, même ce qui est déjà résumé ici.

customAttributeRenderers

Injectez votre propre contenu, avant ou après le texte

Un identifiant métier, un badge de statut, n'importe quoi de spécifique à votre projet : votre fonction reçoit la valeur déjà résolue de l'attribut visé, plus un contexte donnant accès à tous les autres attributs de l'objet.

renderPackageToHtml(pkg, { customAttributeRenderers: [{ attribute: "PUID", position: "before", render: (value) => value?.kind === "STRING" ? `<span class="puid">${value.value}</span>` : undefined, }], })
Badge PUID via customAttributeRenderers EN DIRECT

Une balise mal fermée dans votre render() ? Détectée et neutralisée automatiquement (texte échappé + avertissement console) plutôt que de casser toute la mise en page qui suit.

contentAttributes · titleAttributes

Choisissez exactement ce qui sert de titre et de contenu

Par défaut, le titre vient du LONG-NAME et le contenu de tous les attributs XHTML. Si votre schéma range les choses ailleurs (un attribut ChapterName pour le titre, un seul ReqIF.Text précis pour le corps), reprenez la main.

renderPackageToHtml(pkg, { contentAttributes: ["ReqIF.Text"], titleAttributes: ["ChapterName"], })
contentAttributes / titleAttributes explicites EN DIRECT
chapterNumbers · chapterNumberAttributes

Numérotation façon Word — seulement sur les vrais chapitres

Activé seul, chapterNumbers numérote tout le monde. Avec chapterNumberAttributes, seuls les objets porteurs de cet attribut comptent comme des "titres" — les exigences ordinaires entre deux chapitres ne décalent pas la numérotation, exactement comme un paragraphe entre deux titres Word.

renderPackageToHtml(pkg, { chapterNumbers: true, chapterNumberAttributes: ["ChapterName"], })
Numérotation des chapitres EN DIRECT
readingMode

Une vue de lecture propre, façon document Word

Masque le badge ID, la ligne créé/modifié et le panneau technique ; les titres deviennent des balises <h3>–<h6> de taille fixe (pas de rétrécissement en cascade sur les arborescences profondes). Le contenu que vous ajoutez via customAttributeRenderers reste affiché.

renderPackageToHtml(pkg, { readingMode: true })
readingMode (+ numérotation + placeholders propres) EN DIRECT

À l'activation, la démo combine aussi chapterNumbers et les options "vide volontaire" vues plus bas — pour un vrai rendu Word, les trois vont généralement ensemble.

layout: "tabs"

Plusieurs documents ou spécifications, en onglets

Pour un .reqifz à plusieurs modules, ou simplement plusieurs Specification dans un même document. Implémenté en CSS pur (case radio cachée + sélecteurs :checked ~) — aucun JavaScript, fonctionne même si le HTML est inséré statiquement.

renderDocumentToHtml(doc, attachments, { layout: "tabs", })
layout: "tabs" (puis cliquez les onglets — CSS pur, eux aussi réels) EN DIRECT
SpecRelation

Les liens de traçabilité, enfin visibles

Chaque exigence affiche ses liens sortants (→) et entrants (←), avec le type de relation et un lien d'ancrage vers l'objet visé s'il est rendu sur la même page. Activé par défaut, y compris en readingMode — un lien de traçabilité est du contenu, pas de la métadonnée.

// activé par défaut const html = await renderPackageToHtml(pkg); // décoché ci-dessous : { showRelations: false }
showRelations EN DIRECT
isTitleless · isContentless

"Sans titre" et "vide" ne sont pas toujours des erreurs

Un titre de chapitre pur n'a souvent aucun contenu propre ; un objet "Information" a du texte mais n'est jamais censé avoir de titre. Dans ces deux cas, "(sans titre)"/"(vide)" ne sont pas des données manquantes à signaler — ces deux fonctions, totalement indépendantes l'une de l'autre, le disent à la bibliothèque.

renderPackageToHtml(pkg, { isTitleless: (obj, specType, index) => { const { value } = resolveAttribute(obj, index, "ObjectType"); return valueToPlainText(value, index) === "Information"; }, })

sécurité

Le contenu XHTML est traité comme non fiable, point final

Liste blanche stricte de balises/attributs (alignée sur la clause 10.8.20 de la spec) : <script>, formulaires, style hors propriétés autorisées, liens javascript: — tout est neutralisé à l'import, pas seulement masqué par CSS.

Les exports principaux

Détail complet de chaque option dans le README.md du paquet ; le fonctionnement interne (algorithmes, complexité) est dans ALGORITHMES.md.

ExportRôle
loadReqIfPackage(input, opts?)Charge un .reqif ou .reqifz (string/bytes), détecte le format automatiquement.
parseReqIfXml(xml, opts?)Parse une seule chaîne XML ReqIF en modèle de données typé.
renderPackageToHtml(pkg, opts?)Rendu HTML complet de tous les documents d'un package.
renderDocumentToHtml(doc, attachments, opts?)Rendu HTML d'un seul document.
renderSpecification(spec, index, …)Rendu d'une seule arborescence de spécification (UI virtualisée).
ReqIfIndexRésolution O(1) des références croisées (types, relations, hiérarchie…).
renderXhtmlContent(content, opts?)Sérialisation assainie d'un fragment XHTML isolé.
resolveAttribute / valueToPlainTextLecture d'un attribut par nom (insensible à la casse/ponctuation) et extraction de texte, quel que soit son type concret.
createAttachmentResolver(fn)Résolveur de pièces jointes personnalisé (pour un .reqif nu avec images servies ailleurs).
